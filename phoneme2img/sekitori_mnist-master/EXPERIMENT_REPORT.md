# Sekitori MNIST 実験メモ

## 目的

この実験の目的は、1つの入力画像に対して複数の正解画像がありうる状況で、VAEの潜在分布がそれら複数の正解を均等にカバーできるかを確認することです。

MNISTでは、入力数字 `d` に対して `d-1`, `d`, `d+1` の3種類の数字画像を教師候補としました。例えば入力が `5` なら、教師候補は `4`, `5`, `6` です。

通常の再構成Lossでは、複数教師の平均画像や最も出しやすい教師に寄りやすいため、このリポジトリでは「席取りLoss」を使います。

## 席取りLossの意図

VAEのencoderが出力する `mu`, `logvar` から多数の潜在変数 `z` をサンプリングし、それぞれをdecoderで画像に戻します。

各生成画像について3つの教師画像とのMSEを計算し、近い教師へ割り当てます。ただし、各教師に割り当てられるサンプル数には上限を設けます。現在は `num_samples=99` かつ教師数3なので、各教師の席数は33です。

意図している挙動は以下です。

1. まだ席が空いている教師だけを候補にする。
2. 各教師ごとに、その教師に近い生成サンプルから順に見る。
3. 現在残っている候補の中で最もMSEが小さい組を貪欲に採用する。
4. ある教師の席が埋まったら、その教師への割り当て候補は以後無視する。
5. すでに別の教師に割り当てられた生成サンプルも以後無視する。

これは厳密な全体最適マッチングではありません。訓練中はencoder分布もdecoderも暫定的であり、MSE行列そのものが学習途中の近似評価なので、局所的に「近いものから席を取る」貪欲法を採用しています。

## 主な変更点

### `loss.py`

`sekitori_loss_sum` と `sekitori_loss_worst_percent` の割り当て処理を修正しました。

以前の実装では、「MSEの小さい順」がどの教師を基準にした順序なのかが曖昧になりやすく、教師の席が埋まった後もその教師とのMSE順が割り当て判断に影響する可能性がありました。

現在の実装では、各教師ごとに生成サンプルをMSE昇順に並べ、席が残っている教師だけを候補にして、その時点で最もMSEが小さい `(sample, teacher)` を貪欲に採用します。席が埋まった教師は以後候補から外れます。

### `data_utils.py`

教師画像を固定画像ではなく、各数字クラスからランダムに選ぶようにしました。

同じ数字の教師についても、入力画像そのものを教師にしないように、入力画像と完全一致する候補を除外しています。これにより、単なる自己再構成ではなく「同じ数字クラスの別画像」を含む多正解問題として訓練できます。

### `train_fixed.py`

ファイル名は既存のままですが、実験内容はランダム教師版に変更しました。

主な変更は以下です。

- 学習時と検証時に `sample_related_images_batch(labels, inputs=data)` を使う。
- TensorBoard logを `runs/vae_sekitori_random_teacher` に出す。
- 画像出力先を `img_random_teacher` にする。
- 10エポックごとにcheckpointを保存する。

checkpointには以下を含めています。

- epoch
- model state dict
- optimizer state dict
- train/val MSE, KLD
- `latent_dim`, `num_samples`, `beta`, `lr`, `track_digit`

### `train_random.py`

既存のランダム教師版スクリプトでも、同じ数字教師が入力自身にならないように `inputs` を渡す形へ合わせました。

### `analyze_checkpoint.py`

学習済みcheckpointを読み込み、最終状態を可視化する解析スクリプトを追加しました。

出力する図は以下です。

- encoderの `mu` をPCAで2次元表示した潜在分布
- encoder分布からサンプルした `z` をPCAで2次元表示した潜在分布
- 各数字入力から生成した画像グリッド
- 実画像と生成画像を画素空間PCAで比較した分布

## 学習条件

主な設定は以下です。

- model: convolutional VAE
- latent dim: 4
- train images: 各数字50枚
- validation images: 各数字10枚
- epochs: 200
- learning rate: `1e-4`
- `num_samples`: 99
- `beta`: 0.1
- 教師候補: `d-1`, `d`, `d+1`
- 各教師の席数: 33

10エポックごとのcheckpointは以下に保存しました。

```text
checkpoints/random_teacher/2026-07-01/
```

`epoch_0010.pt` から `epoch_0200.pt` まで保存されています。

## 最終結果

最終epochの値は以下です。

```text
Epoch 200/200
Train MSE: 45.1075  KLD: 4.0339
Val   MSE: 46.9887  KLD: 3.8014
```

MNIST画像は0から1に正規化されており、MSEは784画素方向の和に近いスケールです。Val MSEが約47という値は、生成画像の見た目としてはかなりぼやけた状態です。

- これはencoderが各入力に対して広い分散を出していることを示します。
- 複数正解をカバーするという意味では望ましい方向ですが、重なりが大きすぎるとdecoder出力がぼやけます。

- 数字ごとの分布も重なりが大きく、画像空間上のクラス分離は弱いです。

## 現時点の解釈

今回の実験では、席取りLossによって「1つの入力分布から複数教師をカバーする」方向の挙動は確認できました。

一方で、生成品質はまだ不十分です。特に以下が問題です。

- encoderの分散が大きく、`z` 分布が数字間で強く重なっている。
- decoderが複数教師を鮮明に出し分けるより、ぼやけた平均的画像を出す方向に逃げている。
- 訓練データが各数字50枚と少なく、decoderが十分にMNIST形状を学習できていない可能性がある。
- `latent_dim=4` は可視化しやすい一方で、複数正解の分岐を表現するには小さい可能性がある。

したがって、席取りLossの割り当て機構は意図に近いですが、VAEとしての生成品質を上げるには追加実験が必要です。

## 次に試す候補

1. 通常VAEまたは自己再構成VAEを同じ設定で学習し、MSEと生成品質のbaselineを作る。
2. `beta` を下げて、KLDによる分散拡大を弱める。
3. `latent_dim` を8や16に増やす。
4. train imagesを各数字50枚から増やす。
5. decoder容量を増やす。
6. 席取りLossに加えて、入力自身または同一数字教師への補助再構成Lossを少量混ぜる。
7. MSEだけでなくBCEやperceptualではないが局所構造を保ちやすい補助項を比較する。

特に次の比較は重要です。

- 通常VAEのMSEはいくつまで下がるか。
- ランダム教師だが席取りなしの場合、生成はどう崩れるか。
- 席取りLossで `beta=0` または非常に小さい値にした場合、ぼけは減るか。

これらを比較すると、現在のMSE 46が「席取りLoss特有の難しさ」なのか、「モデル容量・データ量・VAE設定の問題」なのかを分離できます。
